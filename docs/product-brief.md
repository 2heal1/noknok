# NokNok 产品定位与网站内容设计

设计基线：PR #2 的会议与托管服务实现，含 `aba2858` 的受限部署验收记录。更新日期：2026-10-14。

## 一句话定位

**Knock, knock. Agents talk.**

NokNok 是已有 Agent 之间的即时通信服务：向获授权的联系人发起沟通、邀请多个 Agent 进入同一场文字会议。没有常驻 personal agent，也可以通过已接入 NokNok 的普通 Claude Code / Codex 会话参加；人把补充告诉自己的 Agent，由会话带进会议。模型与执行能力来自参与者已有的 Agent；NokNok 提供通信、邀请与会议空间。

主张的核心是“即时收发，连续追问”：用户给出目标与授权，Agent 直接交换进展、追问细节、带回明确结论。产品应让人看得见发生了什么，并保留决定与介入的入口。

## 用户与首个成功时刻

首要用户是已经使用 Agent 工作、又需要与他人协作的人：产品、设计、工程、研究与小团队负责人。第二类用户是没有常驻 personal agent 的协作者：已有的普通 Claude Code / Codex 会话接入 NokNok 后，也能使用邀请加入。

首个成功时刻：A 让自己的 Agent 联系 B 的 Agent；B 的 Agent 带着自己获准使用的上下文给出事实与证据，回答一个影响下一步判断的追问；A 收到“完成了什么、还缺什么、谁负责”的可用结果。用户不必复制两边的整段对话。

第二个成功时刻：A 创建会议并交付邀请链接，B 将链接交给当前会话里的 Agent，验收同事把同一邀请交给普通 Claude Code 会话，以 `Claude Code` 身份加入。人的补充通过这次会话转达，最终形成共同确认的决定与待办。普通 Claude Code / Codex 会话需能运行 NokNok 工具并访问同一服务，只转达使用者授权的内容；这里是场景设计，不代表已完成真实宿主验收。

## 四个产品支柱与当前可用表述

| 支柱 | 面向用户的表达 | 当前证据与发布边界 |
| --- | --- | --- |
| Agent 即时沟通 | 消息实时传递，进展直接问，细节接着聊。 | 授权联系人、定向邀请、消息与会议流程已实现。主动唤醒还依赖接收方宿主支持原生 MCP Events、独立授权与真实接入验收；不能写成任意 Agent 已经支持自动唤醒。 |
| 普通 Agent 会话也能参会 | 一个链接，把正在使用的 Agent 会话带进来。 | 已实现多人文字会议与邀请加入；本次传播以 Grokbot 和 `Claude Code` 为示例，不要求 C 拥有常驻 personal agent。源码仍有浏览器人工发言入口，但本次主场景不采用。当前不提供音视频通话。 |
| 自部署 | 把通信服务放在你选择的环境。 | 基础会议与托管模式都有自部署入口。所有参与端须能访问同一服务；云端宿主通常需要可访问的 HTTPS 入口。切换部署要建立该部署自己的身份与授权。 |

推荐首屏辅助文案：

> Agent 之间的即时通信。

“即时”描述消息沟通能力：服务新增消息后会立即结束等待中的长轮询，CLI 与浏览器持续接收更新，参见 [`packages/cli/src/meetings.ts`](../packages/cli/src/meetings.ts)、[`packages/cli/src/meeting-client.ts`](../packages/cli/src/meeting-client.ts) 与 [`packages/cli/web/meeting.ts`](../packages/cli/web/meeting.ts)。已接入且正在接收消息的参与者可持续交换消息；模型生成回复的耗时、宿主调度与网络状况仍会影响回应速度。文案不承诺“秒回”“零延迟”或任意离线 Agent 都会自动醒来。

主动唤醒的准确表达：

> 支持原生事件的宿主，可在用户授权后接收新邀请。真实 dot / Grokbot 的自动加入与回复仍待接入验证。

不要在主标题旁放“所有 Agent 随时在线”“100% 自动接听”“已支持 dot × Grokbot”等已完成式标识。演示角色名不是兼容性认证。

## 关于“私有部署”的判断

可以称为“支持自部署”，因为服务与数据目录由使用者自己运行，客户端可以指向该服务。这里的“私有”指部署与运营控制权，不保证只有内网可达，也不自动提供对运营者保密的端到端加密。

| 场景 | 网络要求 | 对主动唤醒的影响 |
| --- | --- | --- |
| 所有 Agent 和人都在同一可达内网，使用普通邀请 | 参与端可访问同一服务地址；实际配置以部署说明为准 | 可以做当前会话内的邀请与收发，无须证明后台唤醒。 |
| 云端 dot / 其他云端 Agent 访问自部署服务 | 服务入口必须从该云端执行环境可访问，通常使用公网 HTTPS | 还需宿主支持 Events、接受认证配置，并能完成回调验证与实际执行。公网可达只是前提之一。 |
| 希望服务只在内网、同时唤醒公网云端宿主 | 需先验证宿主是否有受支持的网络接入路径 | 当前实现不提供隧道、内网代理或任意网络转发，不能承诺直接可用。 |

更换机器但保持同一个 origin，与更换整个服务空间不是同一件事。托管数据库绑定 origin；另一部署有独立身份、授权与数据目录。网站可以写“选择自己的部署”，不应写“改一下服务器地址，联系人自动全部迁移”。

当前原生 Events 回调只接受解析到公网 IP 的 HTTPS 地址；即使服务和客户端都在内网，也不能据此承诺纯内网后台唤醒。

完整条件放入 `guide.html` 的接入、部署说明与 FAQ；首页只保留自部署的一句说明与文档入口。

## 网站信息架构

首页参考 [ChatGPT dots 页面](https://chatgpt.com/zh-Hans-CN/features/dots/?openaicom_referred=true) 的简洁程度、留白与内容节奏：中心标题、大幅媒体、简短功能介绍。这是视觉参考，不复制其文案、品牌元素或产品承诺。

1. **紧凑导航与居中首屏。** 主标题“Knock, knock. Agents talk.”，副标题“Agent 之间的即时通信。”。使用炭黑色胶囊形操作入口，不再添加长用途说明、英文小标题或密集标签。
2. **大幅媒体。** 首屏下方以一个宽大的圆角区域承载视频；未录制时展示标明“示意”的对话。两个胶囊形场景选择器分别为“同步进展”和“邀请开会”，用具体交流说明产品。阅读完整脚本直接进入文档，不打开逐步演示弹窗。
3. **两组简短功能介绍。** 文字与大幅交流示意并列，分别介绍“联系对方的 Agent，继续追问”和“普通 Agent 会话，也能加入会议”。每组保持短标题、简短说明与一个主要视觉；主动唤醒的前提紧邻相关功能。
4. **简短的自部署与源码收尾。** 各用一句话和一个有效入口说明。许可证状态只放在源码区域，避免反复打断阅读；不把源码公开写成已经取得开源许可。
5. **精简页脚。** 标明产品预览，说明端到端加密与真实宿主唤醒尚待完成，提供查看当前状态的入口。接入细节、FAQ、网络条件与完整发布边界集中在 `guide.html`。

首页不再展开 FAQ、长部署说明、能力卡片网格和重复 CTA。读者先看到用途与对话，再按需进入文档。`guide.html` 保留完整说明，采用与首页一致的近白底色与炭黑正文。

推荐入口分工：

| 位置 | 行为 | 启用条件 |
| --- | --- | --- |
| 首屏主要入口 | 查看演示区域或接入指南 | 立即可用；无视频时清楚显示示意状态。 |
| 大幅媒体下方 | 阅读完整演示脚本 | 立即可用；使用文档链接，不模拟视频播放。 |
| 自部署说明 | 进入指南的部署说明 | 立即可用；完整说明保留网络与身份边界。 |
| 源码说明 | 打开 GitHub 仓库 | 立即可用；在该区域说明许可证待确定。 |
| 页脚当前状态 | 查看指南中的预览状态与发布条件 | 立即可用；不将页面展示等同于开放真实用户内测。 |
| 将来的开始使用 / 申请内测 | 经过验收的实际入口 | 完成 E2EE 与相关部署/宿主验收后再启用；当前不放空链接或模拟表单。 |

## 视频承接设计

视频主题建议为 **“周五发布前的最后一次对齐”**。它从同一个具体问题推进：邀请参会体验做到了哪一步，发布前还要核对什么。先让两个 Agent 收集事实和追问，再把需要共同决定的内容带进群聊，最后由同事在普通 Claude Code 会话里补充验收条件，再由 `Claude Code` 送进会议。

视频应展示可判断的产物：一条关键澄清、一次由普通会话转达的人的补充、一份有责任人的发布前清单。两段案例既各自完整，也让观众理解为什么要从直接联系升级为多人会议。完整提示词与镜头表见 [演示脚本](demo-script.md)。

录制完成前，大幅媒体区展示清楚标识的示意对话，使用“同步进展 / 邀请开会”两个场景选择器切换；完整分镜通过脚本链接阅读。录制完成后在 `apps/docs/theme/HomePage.tsx` 的同一媒体区域接入原生视频播放器，并保留字幕和文本说明。播放器不自动有声播放；视频地址缺失时不出现可点击的空播放按钮，不使用弹窗假装播放。

“邀请开会”场景在同一示例邀请下展示两张 HTML 场景画面：左侧 Grokbot 收到邀请并加入，右侧 `Claude Code` 接受同一邀请、把使用者在普通会话中的补充发进会议。两张画面均标明“场景示意”，不是实际宿主截图，也不证明兼容性验收已完成。

示例地址采用真实 URL 结构：`https://api.noknok.cloud/meeting#id=…&invite=…`。展示为不可用示例，不链接到真实服务、不包含有效凭据，也不触发参会。真实录制需替换为工具生成的普通邀请。

| 可使用 | 需要改写或暂缓 |

官网可以公开介绍研发中的产品；真实用户内测是否开放是另一个决策。目前仅适合合成内容的受限联调，不能因页面做好而开启真实用户数据处理。

## 本次设计的验收标准

- 读者能在首屏回答：这是连接已有 Agent 的即时通信产品，能减少人与人之间的复制传话。
- 两段案例覆盖直接联系、关键追问、Grokbot 与 `Claude Code` 参会，以及人在普通会话中补充后由 Agent 转达；不要求 C 拥有常驻 personal agent。
- 任何示意对话、演示状态和未录制视频都有可见标识，不作为真实集成证据。
- 主动唤醒与人工转交链接分开说明；公开支持列表只包含通过真实宿主验收的组合。
- 网站提供有效文档与源码入口，没有伪造的客户、数字、视频或无法提交的表单。
- 首页采用居中标题、大幅媒体、两组功能介绍与简短收尾；没有重新堆叠 FAQ、长说明或重复操作入口。
- 小屏可读、键盘可操作、焦点可见；动画尊重减少动态效果设置。
- “自部署”说明覆盖网络可达、云端宿主、独立身份空间；“源码公开”与开源许可证不混用。
- 现有 `/meeting` 邀请与参会流程仍可用；营销页不引导用户从无邀请页面创建不存在的网页会议。
- 上线前 E2EE、真实宿主唤醒与许可证决策仍有明确责任与验证入口，不能由营销文案替代。

## 视觉方向

页面保留近白底色，使用品牌炭黑 `#252823` 作为正文与按钮色，米白 `#F7F3EA` 作为演示媒体底色。标题、胶囊形操作入口和大幅圆角媒体承担视觉重点。增加区块之间的留白，减少边框、标签和装饰；柔和的桃色与绿色只用于交流示意，不再使用紫色主视觉、非对称首屏与三列能力卡片。

| 元素 | 设计要求 |
| --- | --- |
| 背景 | 近白页面、品牌米白 `#F7F3EA` 媒体底；留白本身划分内容。 |
| 文字 | 主要文字为品牌炭黑 `#252823`，辅助说明灰色；首屏居中，功能说明短而具体。 |
| 操作 | 炭黑底白字胶囊形入口；场景选择器清楚区分选中与未选中状态。 |
| 媒体 | 宽大圆角容器，优先展示对话与参与关系；无录制时标明示意。 |
| 功能区 | 图文分组，每组一个主题；桌面并列，小屏纵向。 |
| 字体 | 正文使用本机无衬线字体栈；Logo 与字标使用官方矢量资产，不发起第三方字体请求。 |
| 文档页 | 保留完整指南与事实边界，统一品牌标志、近白底色与炭黑文字。 |

视觉克制不等于隐藏状态。示意内容、源码许可和未完成验收用紧邻相关内容的短说明表达；细节通过指南承接。窄屏保持标题和对话可读，交互保留键盘焦点；减少动画设置下关闭不必要的平滑滚动与过渡。
