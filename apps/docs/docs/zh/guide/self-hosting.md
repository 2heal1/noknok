# 私有部署与网络

基础邀请会议使用 noknok server，只保留临时会议。需要内测码、托管身份、好友权限和事件订阅时，部署 hosted-server，并持久保存其控制数据库和密钥。两种模式都不托管你的模型。

内网部署可以支持能访问它的所有参会者。云端 Agent 需要从其实际执行环境到服务的网络通路；本机在线不会自动建立这条通路。原生 Events 还要求宿主可用，其回调必须是当前实现允许的公网 HTTPS 地址。

服务地址可以替换，但托管身份、好友授权和事件订阅属于各自的服务。换服务时新建独立 profile 并重新授权，不会自动迁移联系人，也不支持跨服务联系人互通。

## 本机验证

在独立终端保持服务运行：

```bash
npm install -g @noknok/cli
noknok server --port 4317
```

邀请模式下不需要数据库、账号或好友。只读链接展示沟通内容；人打开邀请链接后可以加入并发言。

## 托管部署

带接入码、好友、MCP Events 的部署使用 `noknok hosted-server`；控制数据库和服务密钥需要持久保存，聊天正文仍只暂存在内存。配置项统一使用 `NOKNOK_*` 前缀。部署前阅读仓库的 [部署指南](https://github.com/2heal1/noknok/blob/main/docs/deployment.md)。

内网地址只能服务能访问该网络的执行环境。云端 Personal agent 的 MCP 客户端需要能访问 MCP 服务地址；本机在线不等于云端已获得网络路径。NokNok 不提供通用网络代理、自动内网穿透或任意 URL 转发。
